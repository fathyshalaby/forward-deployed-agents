# Embed the FDE into the product MCP

**Preferred deploy path.** The forward-deployed agent is a set of tools and
playbooks that live on the **product team's MCP server** (or a minimal MCP you
scaffold in their repo). Customers connect Claude / ChatGPT to *that* server.
No separate FDA process required.

The Python `fda serve` in this repository is a reference implementation and
local demo — not the default for production products.

## Who owns what

| Piece | Owner |
|---|---|
| MCP process / URL customers hit | Product |
| Credentials, OAuth, DB | Product |
| Playbooks, connector descriptors, artifact recipes | Product (generated by the skill) |
| Plan → approve → run → audit policy | Implemented in-product (this contract) |

## Tool contract (add to their MCP)

Expose at least:

```
agents.list, agent.describe
plays.list, play.describe, play.plan, play.run, play.status
approval.status          # grant is human-only in production
audit.explain, ops.status
artifacts.list, artifacts.get   # optional but recommended
```

Semantics (match the reference runtime):

1. **Plan before act.** `play.plan` returns steps + approval ids; executes nothing.
2. **Human grants writes.** Production must not let the model call grant.
3. **Fail closed.** Denial or missing scope stops the run.
4. **Content-free audit.** Store hashes / ids / connector actions, not free text.
5. **Artifacts read-only.** Claude artifacts may call read tools only; writes stay
   in chat after approval.

Input/output shapes can follow `src/fda/tools.py` and `docs/boilerplate.md`
§ JSON HTTP API — same ideas, hosted on their MCP instead of `fda api serve`.

## Connectors in-process

When the MCP runs inside the product boundary, a "connector call" is a normal
function that uses the product's secret manager / OAuth tables. You do **not**
need HMAC webhooks back into yourself. Webhooks remain useful only when a
sidecar or another language process must call the product over HTTP.

## Scaffold

| Path | Use |
|---|---|
| `examples/embed/typescript/` | Minimal Node MCP with FDE tools + sample play |
| `examples/bundles/specky-fde/` | Declarative Specky-shaped plays + artifact recipe |

Copy the TS folder into the product monorepo (or port the handlers to their
existing MCP framework). Point Claude Desktop / ChatGPT at **their** command or
URL.

## Setup interview (what the skill walks through)

1. Existing MCP or scaffold new?
2. Customer jobs (1–3) and systems touched
3. Who approves writes + how (in-app / Slack / …)
4. Primary customer channel (Claude / ChatGPT / artifacts / in-product)

## Definition of done

On **their** MCP: plan → human grant → run → audit. Customers' Claude/ChatGPT
config points only at the product MCP. Optional artifact recipe builds against
those read tools.
